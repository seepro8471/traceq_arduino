### 사장님 결정 (10-13 밤) — 설정기(ArduinoConfigurator)는 출하물에서 뺀다
설정기가 하던 일은 다른 곳이 덮는다: 태그 발급 세 종류 = 세척관리 태그 창(`cfg_new_tag`) · 시계 = 세척관리가 연결마다 자동 + 업로더 + 리더기 메뉴 ·
타입·번호·알람·세척/소독 시간·환자확인·일회성 담당자·MaxCount·딜레이·슬롯 = 리더기 메뉴. 설정기만 하던 것(설정값을 PC 화면에서 한눈에 읽기 ·
액교환 횟수·교환일을 숫자로 고치기 · MaxCount·딜레이 100 이상)은 드문 보정이라 그때만 저장소에서 꺼내 쓴다. 19차까지 설정기에서 나온 문제
(시각 칸 굳음 · 서버 리더기에 물린 채 기록 지워짐 · 휠로 값 바뀜)는 전부 "현장에 설정기가 물려 있을 때" 의 일이었다 — 배포하지 않으면 생기지 않는다.
코드는 지우지 않는다(저장소에만 둠 · 관문·배포 밖).

## 사장님 결정 (09-28) → v2.2.31 — 게이트웨이 본체번호를 설정값에도 반영

사장님 확인: *"PC 는 0 을 못 주게 막았어. 번호가 틀릴 때만 1회 기록 — 설정값을 바꾸게 해줘."*

2.2.6 은 PC 가 준 번호(`G1`)를 **RAM(`mGateNumber`)에만** 두고 태그·화면에만 썼다(그때 사장님도 *"그냥 둬"* 로 닫으셨다). 이번에 **설정값(EEPROM)까지** 반영한다 — **다를 때만 1회**.

- **찢김에는 더 강하다**: 쓰기가 찢겨 번호가 틀어지면 **다음 `G1` 이 다시 쓴다**. 설정기·메뉴 경로는 스스로 낫지 않는다(`SetNumber` 의 12차 판정).
