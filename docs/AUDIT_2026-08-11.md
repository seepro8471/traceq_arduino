# TraceQ Arduino 전체 로직 감사 — 2026-08-11 (v2.2.4 → v2.2.5)

6개 영역(main·시리얼 / RFID·태그IO / 업무 프로세서 / UI·LCD·NVM / 메모리·빌드 /
업로더·도구)을 나눠 전수 분석하고, 지적 사항을 코드에서 직접 재확인한 뒤
확정된 것만 수정했다. 실기 검증된 동작(nested authentication, 태그 1회 처리,
3단 거부, 와이어 프로토콜)을 되돌리는 제안은 전부 기각했다.

## 수정 완료 (v2.2.5)

### RFID 암호화 상태 — 가장 심각했던 결함
2.1 에서 "섹터 전환 시 `StopCrypto1` 금지"를 실기로 확립했는데, **같은 규칙이
적용되지 않은 경로 두 곳**이 남아 있었다. 카드는 인증 후 암호화 상태를 유지하므로
리더만 평문화하면 그 세션의 이후 인증이 전부 실패한다.

| 경로 | 증상 | 수정 |
|---|---|---|
| `Read()` 실패 | 서버 덤프에서 **1회 읽기 실패 → 이후 모든 블록이 0 으로 전송**. 로그도 경고도 없이 빈 기록이 서버에 저장 | 캐시만 버리고 nested 재인증 후 **1회 재시도**. 실패해도 세션 유지 |
| `InstallTraceQKeys`/`RestoreFactoryKeys` | 태그 발급(`cfg_new_tag` type 0·2)이 **결정적으로 실패** (2.1 신규 기능, 실기 미검증이라 드러나지 않음) | 중간·끝의 `StopCrypto1` 제거 — 1.4.1 과 동일하게 연속 인증 |

구조 정리: 암호화 상태(`mCryptoOn`)를 인증 캐시와 **분리 추적**하고,
`dropAuthCache()`(세션 내부 복구, StopCrypto1 금지) / `stopCrypto()`(세션 경계,
무조건 해제)로 역할을 나눴다. `EndSession()` 은 HaltA → StopCrypto1 순서를 보장한다.

### 업무 로직 (1.4.1 승계 결함)
- **기록 커밋 순서**: 소독 시작의 `write_process()`, 게이트웨이의 `Status=1` 을
  블록 기록보다 **뒤로** 이동. 중간 실패 시 "소독했다/환자정보 있다"는 플래그만
  서고 실제 기록은 비어 있는 태그가 남던 것을 차단(최종 바이트는 동일).
- **소독 횟수 오계상 2건** — 액교환 주기 판단에 직결:
  - 더블터치 2초 가드로 시작이 재실행될 때 횟수가 한 번 더 올라감 → `isRestart` 로 차단
  - 동시소독 guest 슬롯이 종료 터치 없이 남으면 그 스코프가 **이후에도 계속 guest 로
    판정되어 횟수가 오르지 않음** → 시간창 판정을 승격이 아닌 **대입**으로 정정
- 스코프 번호를 `uint8_t` 로 비교하던 것을 `int16_t` 로(5번과 261번이 같아지고
  255번이 "빈 슬롯" 센티널과 구별되지 않던 문제)
- 거부로 끝난 경우 이동 플래그(`mMovable`) 해제 — 남으면 나중 태그가 의도치 않게 이동 처리
- `GatewaySerialEvent` 진입 시 `mDateTime` 초기화 — G2 없는 패킷에서 **직전 검사 날짜**가 기록되던 것

### 안정성
- 메뉴 숫자 버퍼 `char[3]` + `"%02d"` 5곳 → 값이 100 이상이면 스택 침범 (JSON 원격
  설정으로 도달 가능). 버퍼 확대 + `snprintf`
- `abort()` 18곳 → `util_soft_reset()`. avr-libc `abort()` 는 `cli(); for(;;);` 라
  **전원을 뽑기 전엔 복구 불가**였다
- `DeviceOption::GetType()` 화이트리스트 폴백 — EEPROM 1바이트 손상이 영구 정지로 이어지던 경로 차단
- 동시소독 지연 상한 클램프(>120 → int8 음수로 시간창 무효화)
- 매니저 태그 ID 표시가 NUL 없는 14바이트를 읽던 것
- READER_MODE JSON 출력의 트레일링 콤마(매니저/기타 태그)

### 응답성
- **Home 화면을 매 루프 전부 다시 그리던 것 → 바뀐 항목만**. 100kHz I2C 에서 51자
  재출력이 루프의 최대 지연원이었다. 화면을 지우는 경로에는 `InvalidateHome()` 배선
- 시리얼 수신 타임아웃 **1초 → 150ms**. `readBytes` 는 바이트마다 이 시간을 기다리므로
  패킷 수신 후 1초를 더 붙들려 loop 가 멎었다. 부수 효과로 **두 G 패킷이 한 버퍼로
  합쳐져 먼저 온(옛) 환자정보가 채택되던 위험**도 축소

### 진단
- 태그 읽기 **실패 사유**를 LCD 에 표시(`RfidResultName`). 회사코드 불일치는 1.4.1 대로
  무음 — "우리 태그가 아님"과 "읽기 실패"를 구분할 수 없던 것이 현장 진단을 막고 있었다
- legacy 덤프 중 읽기 실패가 있었으면 전송 후 `Read Error` 경고(와이어 바이트는 불변)

### 초기화 규칙 정정
빌드 도장의 재료를 `__DATE__ __TIME__`(= main.cpp 재컴파일 시각) → **버전 문자열**로.
전자는 lib 의 .cpp 만 고친 빌드에서는 초기화가 안 되고 무관한 헤더를 건드리면 초기화가
도는 비결정적 규칙이었다. 이제: **버전이 오른 펌웨어를 올리면 완전 초기화, 같은 버전
재업로드는 설정 유지.**

## 보류 — 사용자 판단·실기 필요

| 항목 | 내용 | 왜 보류 |
|---|---|---|
| **SPI 125 kHz** | MFRC522 1.2.0 이 `SPISettings(SPI_CLOCK_DIV4=0, …)` 로 클럭 0 을 넘겨 최저속(fosc/128)으로 동작. 의도는 4 MHz — **32배 느리다** | 라이브러리 벤더링 필요. 브레드보드 배선에서 고속은 CRC 오류 위험 → 1 MHz 부터 단계적 실기 필요 |
| **하드웨어 타임아웃** | `TModeReg` 대신 `TxModeReg` 에 0x80(1.4.1 승계 오탈자) → TAuto 미설정 → 무응답 판정이 하드웨어 25ms 가 아닌 소프트 카운터. HaltA 는 **성공 조건이 타임아웃**이라 태그마다 낭비 | 무응답 판정이 크게 빨라져 약결합 태그에서 회귀 가능. 사전 레지스터 실측 → 약결합 소크 필요 |
| **중복 `ClearSector`** | 소독 시작이 섹터 5·6 을 지운 뒤 같은 블록을 다시 씀 | 위 두 건 적용 후 함께 측정하는 편이 효율적 |
